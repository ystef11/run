## 1. Главное

1. Длинная пробежка у объёмных планов (80 км) стартует с потолка и затем **уменьшается** (марафон: 150 → 135 → 105 мин); число пробежек скачет 5 → 8–9.

4. Дата цели по умолчанию — понедельник: в плане лишняя неделя из одного дня гонки.
5. В коде остались неиспользуемые остатки старой логики (раздел 5).

## 4. Что править (по приоритету)

**P1. Длинная пробежка и число пробежек**
- Строка 818 (`longCapFor`): доля длинной зависит от числа пробежек (`wkRuns<=5` → 40 %, иначе 25 %). Добавление пробежки уменьшает длинную. Сделать долю независимой от числа пробежек.
- Строки 1279–1280, 963–965: `longPrev` берётся из последней недели, поэтому снижение переносится дальше. Вне разгрузки/подводки длинную не уменьшать.
- Строка 962: привычная длинная = потолок (`longCapFor(curMin)`). Для 80 км это 150 мин с первой недели без роста. Брать привычную долю от текущего объёма, потолок достигать ростом.
- Строка 1225: перебор `r2` берёт первое число пробежек, где недобор < 5 мин. Недобор в 11 мин на 5 пробежках даёт скачок до 8–9. Добирать минуты удлинением лёгких / 2-й тренировкой, а не перестройкой недели.
- Почему: в описании длинная растёт к пику, неделя имеет устойчивую структуру.

**P1. Набор Z5 / Z3+Z4**
- Строка 1045: типы качественных ставятся по абсолютным минутам (`def`), а не по относительному дефициту доли. Тип с большой минутной долей (порог) всегда первый, Z5 не получает слотов.
- Строка 1038: `tgt34`, `tgt5` посчитаны, но не используются — остаток относительной логики. Вернуть сортировку по `факт / цель` каждой зоны.
- Почему: цель 80/6/14 (5 и 10 км) и 75/22/3 выполняется только по Z1+Z2.

**P1. Уровень и пик по времени**
- Строка 581 (`levelFor`): уровень выбирается по `curMin` (минутам). Бегун с теми же км, но быстрее, имеет меньше минут → ниже уровень → меньший пик.
- Определять уровень по км/нед (или по большему из показателей), не уменьшая время у более быстрого.
- Почему: медленный не должен получать больше времени, чем быстрый.

**P1. Дата цели по умолчанию**
- Строка 2026: `goalD = start + недели·7` (понедельник). Строка 681: `N = floor(diff/7)+1` → N+1 недель, последняя — одна гонка. Строки 1866, 2207 используют `round(diff/7)`.
- Исправить: цель = `start + недели·7 − 1` (воскресенье); пересчёт недель из даты — одной и той же формулой с `N`.

**P2. Прочее в генераторе**
- Строка 1320: `recRuns` — максимум по неделям; форма показывает 9. Брать моду недель до подводки.
- Строка 1300–1313: заявленный пик не достигается (марафон 80/37: 102 vs 92). Расхождение показывает, что прогноз пика и генерация недель считают по-разному; свести к одному расчёту.
- Строка 905: `maxQ` не используется.
